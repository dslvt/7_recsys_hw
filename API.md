# Как запустить проверку

Из каталога задания выполните:

```sh
python3.11 -m pip install -r requirements.txt
python3.11 -m pytest -q tests/test_public.py
python3.11 run.py --model baseline
python3.11 run.py --model sasrec
python3.11 run.py --model bert4rec
```

После реализации TIGER запустите `python3.11 run.py --model tiger --seed 42 --epochs 1`.

По умолчанию `run.py` читает данные из `data/` рядом со скриптом и проверяет модель только на `val`. Файл `test.json` для этого не нужен. Другой каталог данных можно указать через `--data-dir`. После выбора настроек добавьте `--split test` для итоговой проверки или `--split both` для проверки на обеих выборках.

| `--model` | Что делает скрипт |
|---|---|
| `baseline` (по умолчанию) | Считает частоту фильмов в обучающих историях, включая повторы. Сортирует весь каталог по убыванию частоты, а при равенстве по возрастанию числового ID. |
| `tiger` | Один раз вызывает `fit` для вашей модели. Передаёт каталог, обучающие истории и число эпох. |
| `sasrec`, `bert4rec` | Один раз загружает готовую модель из `checkpoints/` рядом с `run.py`. Не вызывает `fit`, даже при `--split both`. Другую папку с весами можно указать через `--checkpoint-dir`. |

## Данные и метрики

| Файл | Формат JSON |
|---|---|
| `catalog.json` | Объект: ключом служит строковый ID товара, значением служит список числовых признаков. Длина списка у всех товаров одинакова. Скрипт переводит ключи в `int`. ID не обязаны идти подряд. |
| `train.json` | Объект со списком ID товаров для каждого пользователя в порядке времени. Модель получает списки без ключей пользователей. |
| `val.json`, `test.json` | Массив пар `[history, target]`. История содержит целые ID товаров и может быть пустой. `target` содержит один целый ID следующего товара. |

Для каждой пары скрипт один раз вызывает `recommend(history, k=10)`. Выбор идёт из всего каталога, без случайной выборки кандидатов. Товары из истории остаются кандидатами. Верните список из `min(10, len(catalog))` разных целых ID из каталога в порядке рекомендации. При неверном списке скрипт завершится с ошибкой и не выведет метрики.

Для `k=5` и `k=10` скрипт берёт первые `k` позиций одного и того же списка. Если `target` стоит на месте `r` от 1 до `k` включительно, вклад в `Recall@k` равен `1`, а в `NDCG@k` равен `1/log2(r+1)`. Иначе оба вклада равны нулю. Например, шестое место даёт ноль на срезе 5 и попадание на срезе 10. Каждая метрика усредняется по **всем парам** выборки. Для пустой выборки все четыре значения равны нулю.

Скрипт печатает JSON без округления. Например, если на тестовой выборке не было попаданий, вывод будет таким:

```json
{"test": {"Recall@5": 0.0, "NDCG@5": 0.0, "Recall@10": 0.0, "NDCG@10": 0.0}}
```

## Что реализовать в `submission.py`

- `residual_quantize(x, codebooks) -> (codes, quantized)`: на вход подаются вещественные тензоры `x[N,D]` и `codebooks[L,K,D]` на CPU. Начните с остатка `x`. На каждом уровне для каждой строки найдите ближайший вектор по квадрату расстояния L2 и вычтите его из остатка. При равенстве выбирайте меньший индекс. Верните индексы `[N,L]` типа `torch.long` и сумму выбранных векторов `[N,D]`.
- `make_semantic_ids(item_codes: dict[int, tuple[int,...]]) -> dict[int, tuple[int,...]]`: сгруппируйте товары с одинаковым кодом. Внутри каждой группы отсортируйте товары по возрастанию числового ID. Допишите к коду номер товара в этом порядке, начиная с нуля. Для группы из одного товара тоже добавьте `0`.
- `beam_search(step, valid_ids, beam_size, k) -> list[tuple[int,...]]`: `valid_ids` содержит разные непустые кортежи одной длины с неотрицательными локальными индексами токенов. Начните с префикса `()` с оценкой ноль. Функция `step(prefix)` возвращает одномерные логиты для всего словаря следующего токена. Сначала примените `log_softmax` ко всему словарю, затем оставьте допустимые продолжения из каталога. Не нормируйте их повторно. Прибавьте логарифм вероятности токена к оценке префикса. На каждом шаге объедините кандидатов от всех префиксов и оставьте первые `beam_size` по убыванию суммарной оценки. При равенстве выбирайте лексикографически меньший кортеж. Верните полные ID в этом порядке, не больше `min(k, beam_size, len(valid_ids))`.
- `TIGER(seed: int = 42).fit(catalog: dict[int,list[float]], histories: list[list[int]], epochs: int = 1) -> self`: обучите на CPU токенизатор признаков и модель, которая предсказывает семантический ID по истории. Сохраните соответствие между товарами и семантическими ID в обе стороны. Верните `self`. Классы нейросетей в заготовке можно менять.
- `TIGER.recommend(history: list[int], k: int) -> list[int]`: после `fit` верните ровно `min(k, len(catalog))` разных ID из каталога для любого `k >= 0`. Поддержите пустую историю. Оставьте в выборе товары из истории. Если декодирование дало слишком мало товаров, начните поиск заново с более широким лучом. Ширину можно увеличить до размера каталога.

## Примеры для проверки своей реализации

```python
import torch
from submission import TIGER, beam_search, make_semantic_ids, residual_quantize

x = torch.tensor([[1.0], [3.0]])
books = torch.tensor([[[0.0], [2.0]], [[0.0], [1.0]]])
codes, q = residual_quantize(x, books)
assert codes.tolist() == [[0, 1], [1, 1]]  # Для первой строки на уровне 0 расстояния равны.
assert q.tolist() == [[1.0], [3.0]]
assert make_semantic_ids({9: (4,), 2: (4,), 5: (1,)}) == {
    2: (4, 0), 9: (4, 1), 5: (1, 0)}

# После (0,) большая часть вероятности у недопустимого токена 1.
# Нормировка только по допустимым токенам ошибочно даст ничью.
logits = {(): [0., 0.], (0,): [0., 8.], (1,): [0., 0.]}
assert beam_search(lambda p: torch.tensor(logits[p]), [(0, 0), (1, 0)], 2, 2) == [
    (1, 0), (0, 0)]

model = TIGER().fit({2: [0.0], 9: [1.0]}, [[2, 9], [9, 2]])
assert sorted(model.recommend([], 10)) == [2, 9]
```
