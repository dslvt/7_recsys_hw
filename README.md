# ДЗ 7. Поиск фильмов с помощью TIGER

## Задание

Реализуйте TIGER для киноприложения. Модель получает список фильмов, которые пользователь уже оценил, и выбирает из каталога десять кандидатов для ранжировщика. Верните их `item_id` в порядке убывания вероятности. Проверьте, попал ли в десятку фильм, который пользователь оценил следующим. Учитывайте все оценки, в том числе низкие.

Обучите TIGER на MovieLens 100K. Ваша цель: обойти BERT4Rec по Recall@5, NDCG@5, Recall@10 и NDCG@10. BERT4Rec уже обучена. Её веса лежат в `checkpoints/bert4rec.pt`. Модель популярности оставьте для быстрой проверки данных.

## Как работает TIGER

На слайдах 111 и 112 лекции 7 мы разбирали генеративный поиск. TIGER сначала присваивает каждому фильму короткий код, а затем учится предсказывать код следующего фильма по истории пользователя. Схема обеих моделей есть на рисунке 1 в статье [Recommender Systems with Generative Retrieval](https://proceedings.neurips.cc/paper_files/paper/2023/file/20dcab0f14046a5c6b02b61da9f13229-Paper-Conference.pdf). Подробности обучения описаны в разделе 3.

Токенизатор RQ-VAE строит код по признакам фильма. Энкодер переводит признаки в вектор. В первом словаре токенизатор находит ближайший вектор и вычитает его из вектора фильма. Во втором словаре он ищет ближайший вектор уже к остатку. Номера выбранных векторов составляют код фильма. Декодер складывает выбранные векторы и по их сумме восстанавливает признаки.

Два фильма могут получить одинаковый код. Чтобы различать их, добавьте в конец кода ещё один токен. Например, фильмы `17` и `42` получили код `(3, 1)`. Присвойте им полные коды `(3, 1, 0)` и `(3, 1, 1)`. Если модель предскажет `(3, 1, 1)`, в рекомендации попадёт фильм `42`.

Вторая модель получает историю фильмов в виде таких кодов. Transformer предсказывает токены следующего фильма по очереди. При выборе токена он учитывает историю пользователя и предыдущие токены этого кода. Поиск по лучу (beam search) позволяет проверить несколько продолжений. В задании оставляйте только те продолжения, которые встречаются в каталоге.

Авторы статьи использовали данные Amazon и признаки из Sentence-T5. В этой работе вы получите готовые признаки фильмов из MovieLens. Отдельная текстовая модель не понадобится.

## Первый запуск

Распакуйте стартер в свой репозиторий. Для работы достаточно Python 3.11 и CPU. Выполните команды из корня проекта:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python prepare.py
python -m pytest -q
python run.py --model baseline --split val
python run.py --model bert4rec --split val
```

Сохраните четыре метрики для каждой модели. Команда `bert4rec` загружает готовые веса и сразу считает рекомендации. [BERT4Rec](https://arxiv.org/abs/1904.06690) учится восстанавливать скрытые фильмы внутри истории. При оценке место для предсказания находится в конце истории. В [DATA.md](DATA.md) описаны признаки фильмов, порядок событий и подготовка данных из локального архива. В [API.md](API.md) есть сигнатуры функций и примеры входов и выходов.

## Что написать в `submission.py`

### 1. Токенизатор

Реализуйте `residual_quantize` и обучите RQ-VAE на признаках фильмов. На каждом уровне выбирайте код по текущему остатку. Обучайте энкодер и декодер восстанавливать исходные признаки. Для обучения словарей используйте codebook loss и commitment loss или эквивалентную схему обновления. Передавайте градиент в энкодер через straight-through estimator.

После обучения посчитайте, сколько разных кодов использовал каждый уровень и какая доля фильмов делит базовый код хотя бы с одним другим фильмом. Считайте совпадения до добавления последнего токена.

### 2. Коды фильмов

В `make_semantic_ids` сгруппируйте фильмы с одинаковым кодом. В каждой группе отсортируйте фильмы по числовому `item_id` и добавьте к коду порядковый номер фильма, начиная с нуля. Для группы из одного фильма тоже добавьте `0`.

Сохраните два справочника: по одному находите код фильма, по другому находите фильм по полному коду. Проверьте, что для каждого `item_id` обратный поиск возвращает тот же фильм. При обучении Transformer и при поиске используйте одни и те же коды.

### 3. Предсказание следующего фильма

В `TIGER.fit` подготовьте обучающие пары из всех непустых префиксов, после которых в обучающей истории есть ещё один фильм. Например, из истории `[17, 80, 42]` получатся две пары. По `[17]` модель предсказывает `80`, а по `[17, 80]` предсказывает `42`.

Подайте коды фильмов из истории в энкодер Transformer. Обучайте декодер предсказывать код следующего фильма по одному токену. Например, для цели `(3, 1, 0)` подайте на вход декодера `[BOS, 3, 1]` и сравните предсказания с `[3, 1, 0]`. Различайте токены из разных уровней словаря. Маскируйте padding и будущие позиции декодера. Проверьте на нескольких парах, что ошибка обучения снижается.

Для первого запуска можно взять два уровня квантования, один слой Transformer и несколько последних фильмов из каждой истории. Размеры словарей и модели, длину истории и размер батча выберите сами.

### 4. Поиск по каталогу

Реализуйте `beam_search` и `TIGER.recommend`. Начните с пустого кода с оценкой `0`. На каждом шаге вычислите `log_softmax` по всему словарю следующего токена. Оставьте только те токены, с которыми текущий код совпадает с началом хотя бы одного кода в каталоге. Для каждого такого продолжения прибавьте к накопленной оценке логарифм вероятности нового токена. Из всех продолжений оставьте `beam_size` вариантов с наибольшей суммой. При равных суммах используйте лексикографический порядок кодов.

По полным кодам найдите `item_id` и верните их без повторов в порядке убывания оценки. Проверьте пустую историю, совпадение базовых кодов и запрос, в котором `k` больше размера каталога. В последнем случае верните все фильмы.

### 5. Сравнение моделей

Мы обучили BERT4Rec на MovieLens 100K за 30 эпох и сохранили веса 24-й эпохи по лучшему NDCG@10 на валидации. На валидации BERT4Rec получила Recall@5 0,0541, NDCG@5 0,0341, Recall@10 0,0976 и NDCG@10 0,0481. Сверьте свой первый запуск с этими значениями. Для начисления баллов используйте неокруглённые результаты на тесте.

Получите десять рекомендаций на каждый запрос. Для метрик @5 возьмите первые пять фильмов из этой же десятки. Для всех моделей используйте одинаковые запросы и весь каталог. Не исключайте фильмы, которые пользователь уже оценивал.

У каждого запроса один целевой фильм. Если он занял третье место, Recall@10 для запроса равен `1`, а NDCG@10 равен `1/log2(3+1) = 0.5`. Если фильм занял шестое место, обе метрики @5 равны нулю, но @10 учитывает попадание. Если фильм не попал в десятку, все четыре метрики для этого запроса равны нулю. Усредните значения по всем запросам.

Скрипт подготовки данных оставляет предпоследнюю оценку каждого пользователя для валидации, а последнюю для теста. В тестовом запросе история включает предпоследний фильм, поскольку пользователь уже успел его оценить. Передавайте в `fit` только признаки каталога и обучающие истории. Не читайте файлы MovieLens или готовые веса из `fit` и `recommend`: на проверке эти методы получат другие данные.

На валидации сравните два варианта TIGER, меняя что-то одно. Например, увеличьте историю с 8 до 32 фильмов или поменяйте размер словаря. Если хотите улучшить сами коды, попробуйте добавить к признакам фильма статистику совместных оценок из обучающих историй. Не используйте для этого валидацию или тест. Посмотрите, как изменились доля совпадающих кодов и Recall@10. Сравните два запуска TIGER и выберите конфигурацию. Зафиксируйте параметры, seed и число эпох. Выполните `run.py` для выбранного TIGER и BERT4Rec с `--split test`. Для каждой из четырёх метрик сравните значения из JSON без округления. Цель по метрике достигнута, если результат TIGER строго выше результата BERT4Rec. Равенство не считается победой. Не подбирайте параметры по тесту и не добавляйте события из валидации в обучающую выборку. Не подмешивайте выдачу BERT4Rec в рекомендации TIGER.
