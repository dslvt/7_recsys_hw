# ДЗ 7. TIGER: какой фильм пользователь оценит следующим?

В конце лекции 7 (слайды 111–112) мы сменили способ поиска кандидатов: две башни ищут ближайшие векторы, а TIGER генерирует идентификаторы. В этом задании вы напишете обе части TIGER: токенизатор каталога и модель, которая выдаёт десять фильмов по истории пользователя.

**Легенда.** Вы отвечаете за отбор кандидатов в киноприложении. Сейчас все получают один список популярных фильмов. У команды есть метаданные каталога и журнал оценок. Ваша гипотеза: история взаимодействий подсказывает, в какой части каталога искать следующий фильм. Ранжировщик будет получать от вас только десять `item_id`. Цель офлайн-проверки — попасть в следующий **оценённый** фильм; низкая оценка тоже считается событием. Это не прогноз звёзд и не утверждение, что фильм понравился.

## Как работает TIGER

Разберите рисунок 1 и §3 статьи **Rajput et al., Recommender Systems with Generative Retrieval** [1]. В методе две отдельные стадии обучения.

1. **Превратить фильм в последовательность токенов.** Энкодер RQ-VAE переводит признаки фильма в вектор `z`. Первый словарь выбирает ближайший к `z` вектор; второй кодирует то, что осталось после вычитания первого, и так далее. Индексы выбранных векторов образуют код, а их сумма — приближение `z`. Декодер восстанавливает исходные признаки из этой суммы. Один и тот же начальный токен может оказаться полезным для нескольких похожих фильмов; это выученная общность, а не название жанра. При совпадении полного кода добавляется токен, различающий фильмы [1, §3.1].
2. **Предсказать следующий код по предыдущим.** Замените фильмы в истории их кодами. Transformer читает эту последовательность и авторегрессионно генерирует код следующего фильма: каждый следующий токен зависит от истории и уже сгенерированной части. Несколько гипотез сохраняются с помощью beam search. Справочник `semantic_id → item_id` переводит результат в кандидатов [1, §3.2, 4.5].

Например, пусть фильмы `17` и `42` получили код `(3, 1)`, а фильм `80` — `(5, 0)`. По правилам ДЗ их полные адреса — `(3, 1, 0)`, `(3, 1, 1)` и `(5, 0, 0)`. Если после истории модель сгенерировала `(3, 1)`, выбор **ещё не закончен**. Последний токен `1` вернёт фильм `42`. После префикса `(5,)` разрешено продолжение `0`, но не `1`: адреса `(5, 1, …)` в нашем каталоге нет.

**Границы воспроизведения.** В статье используются данные Amazon и признаки из Sentence-T5. В ДЗ уже есть признаки фильмов: текстовую модель скачивать не нужно. В статье разбираются невалидные сгенерированные ID; здесь потребитель принимает только существующие фильмы, поэтому мы ограничиваем луч допустимыми префиксами. Цифры из статьи не являются порогом оценки [1, §4, 4.5].

## С чего начать

Распакуйте стартер в свой репозиторий. Нужны Python 3.11 и CPU. Из корня проекта:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python prepare.py
python -m pytest -q
python run.py --model baseline --split val
```

`prepare.py` готовит настоящий MovieLens 100K. Где взять исходный архив для офлайн-запуска, как упорядочены события и что содержат JSON-файлы — в `DATA.md`. Форматы функций и примеры — в `API.md`. Сначала запустите уже работающий baseline из `run.py`; сохраните его результат до изменения модели.

## Что реализовать в `submission.py`

| Шаг | Работа | Как проверить себя |
|---|---|---|
| 1. Токенизатор | Реализуйте `residual_quantize` и обучите небольшой RQ-VAE на признаках каталога. Используйте ошибку реконструкции, обучение словарей и commitment loss (либо эквивалентное обновление словарей). Для прохода градиента через дискретный выбор используйте straight-through estimator. | При каждом шаге кодируйте **остаток**, а не исходный вектор. Запишите, сколько кодов занято на каждом уровне и у какой доли фильмов базовый код не уникален. |
| 2. Справочник | В `make_semantic_ids` добавьте детерминированный суффикс по правилам `API.md`, постройте оба направления отображения. Заморозьте адреса до обучения ретривера. | Для каждого фильма `decode(encode(item_id))` возвращает исходный `item_id`, включая фильмы с одинаковыми признаками. |
| 3. Обучение | В `TIGER.fit` нарежьте train-истории на пары «префикс → следующий фильм». Обучите encoder–decoder Transformer предсказывать токены целевого адреса с teacher forcing: вход декодера — `BOS` и предыдущие токены, ответ сдвинут на одну позицию. Различайте уровни словаря, маскируйте padding и будущие позиции декодера. | Для train-истории `[17, 80, 42]` есть пары `([17], 80)` и `([17, 80], 42)`. Вторая пара не даёт модели права читать `42` в энкодере. На нескольких парах проверьте, что loss падает. |
| 4. Поиск | Реализуйте `beam_search` и `TIGER.recommend`. Балл пути — сумма логарифмов условных вероятностей токенов. Отсекайте отсутствующие в каталоге префиксы и возвращайте уникальные фильмы в порядке балла. | Проверьте коллизии, равенство баллов, пустую историю, `k` больше размера каталога. Подробности разрешения ничьих — в `API.md`. |
| 5. Эксперимент | Сравните TIGER с популярностью по Recall@10 и NDCG@10. Один раз измените **либо** ширину луча, **либо** размер словаря и сравните на validation. Для финального запуска зафиксируйте выбранные параметры. | Оцените обе модели на одинаковых запросах и полном каталоге. Для одного пользователя разберите, почему изменилось попадание или позиция цели. |

Начните с двух уровней квантования, короткого окна последних событий и одного слоя Transformer. Сначала добейтесь сквозного запуска на маленьком каталоге. Размеры словарей, ширину модели и стратегию батчинга выбираете вы. Предобученные веса и внешние сервисы для сдачи не нужны.

**Как читать метрики.** Цель на запрос одна. Если фильм оказался третьим, вклад в Recall@10 равен `1`, а в NDCG@10 — `1/log2(3+1) = 0.5`. Если его нет в десятке, оба вклада равны нулю. Итог — среднее по запросам. Кандидаты выбираются из всего каталога; для этого эксперимента уже встречавшиеся фильмы специально не отфильтровываем.

**Протокол:** для каждого пользователя последнее событие — test, предпоследнее — validation. На test история уже включает событие из validation: к моменту запроса оно известно. `fit` получает статические признаки каталога и только train-истории. Не переобучайте модель на validation перед сравнением; test открывайте после выбора конфигурации. Скрытые проверки используют другие входы: не читайте файлы MovieLens и готовые веса из `fit` или `recommend`.
